# secure-host

> This text was generated by an LLM (cgwalters-bot). cgwalters has not reviewed it yet.

One step that secures the machine a job runs on, for whatever the job
does next: a build, a test suite, an agent. Every later step runs as the
runner's user, without root. It is taken from agentic-job's
`docs/secure-host.md`, for this action's contract.

The action runs agentic-job's secure-host image as root podman:

```sh
sudo podman run --rm --privileged --pid=host --network=none -v /:/host IMAGE@sha256:... CONFIG
```

The image holds only agentic-job's static binary and its BPF object. It
installs the binary on the host and sets the host up through the host's
own `nsenter -t 1`, so the BPF links and the network rules outlive the
container. Docker is not used: setup stops it. There is no `exec` command:
nothing runs as another user.

## The contract

The unit of trust is the job. A job that runs code you don't trust holds
nothing worth stealing. A separate job holds the secrets and runs none of
the first job's code. It takes the first job's output by artifact ID and
digest, and validates it as data, as agent safe outputs are handled.

```yaml
on: pull_request
permissions: {}
jobs:
  build:                                     # untrusted: nothing worth stealing
    runs-on: ubuntu-26.04
    permissions: {contents: read}
    outputs:
      id: ${{ steps.up.outputs.artifact-id }}
      digest: ${{ steps.up.outputs.artifact-digest }}
    steps:
      - uses: actions/checkout@<sha>
        with: {persist-credentials: false}
      - uses: cgwalters-forge/actions/secure-host@<sha>  # runs as root: pin it
      - run: make test                       # as the runner's user: no root, writes only by rule
      - id: up
        uses: actions/upload-artifact@<sha>
        with: {name: out, path: out/}
  publish:                                   # trusted: has the secret, runs nothing from build
    needs: build
    runs-on: ubuntu-26.04
    permissions: {contents: read, actions: read}
    environment: release
    steps:
      - uses: actions/download-artifact@<sha>
        with: {artifact-ids: "${{ needs.build.outputs.id }}"}
      - run: verify-digest "${{ needs.build.outputs.digest }}" && validate out/
        env: {TOKEN: "${{ secrets.DEPLOY }}"}
```

The job that runs secure-host has no `id-token` permission and no
secrets, checks out with `persist-credentials: false`, and uses no Docker
actions, `container:` or `services:`. secure-host comes before any step
the job does not trust. Everything that needs root (packages, services,
joining a network) comes before it too.

**What is claimed:** after secure-host, no step gets root or reaches the
cloud metadata service, and writes to world-writable files on the root
filesystem go only to their owner. Steps cannot read another runner
process's environment through `/proc/PID/environ`.

**What is not claimed:** that the steps of one job are kept apart from
each other, or from that job's own tokens. GitHub's step model gives
those to every step.

[The CI workflow](../.github/workflows/secure-host.yml) runs this example,
the inputs, and the world-write policy against the pinned image on
`ubuntu-26.04`, with a positive control before the action for each claim.

## Caveats of running everything as the runner's user

Out of scope: a step tampering with later steps of the same job, through
`GITHUB_ENV`, `LD_PRELOAD`, dotfiles, the tool cache or post-step code.
Any step can compromise the steps after it. The job is the unit of trust.

1. **`ACTIONS_RUNTIME_TOKEN`** (artifacts and caches) reaches every
   JavaScript action, and an earlier step can steer such an action. Run
   untrusted code only on triggers that can't write default-branch caches,
   don't restore in a trusted job a cache the untrusted job could have
   written, and pass artifacts by ID and digest, as data.
2. **The OIDC request token** under `id-token: write` mints tokens for any
   audience: the untrusted job never has `id-token`.
3. **checkout's persisted credentials and `GITHUB_TOKEN`** are readable by
   every step: use `persist-credentials: false` and minimal permissions.
4. **Another process's `/proc/PID/environ`** is refused by the BPF
   runner-read rule, enabled in the default hosted configuration. CI on
   `ubuntu-26.04` checks a later step cannot read a process left by an
   earlier step, with a successful read before the action as control.
   This is not isolation between steps or protection of the job's tokens.
5. **A process left behind** lives until the job ends; the read rule does
   not terminate it. Runner cleanup remains responsible for ending it,
   and the CI job must still finish successfully with the rule enabled.
6. **Container actions** fail with dockerd stopped.
7. **Egress** is open: no proxy and no host-wide rules yet
   (agentic-job#995). Only the metadata service is refused.

agentic-job v0.6 still creates its second, unprivileged user and leaves
the runner's user a sudo rule for `agentic-job sandbox` commands. This
action does not use them, and they give no root.

## Hosts

Exactly **Ubuntu 26.04** and **RHEL 10**, by `ID` and `VERSION_ID` of
`/etc/os-release`; the image refuses any other host before it changes
anything. Only GitHub's hosted `ubuntu-26.04` is tested here. The action
needs `node`, `gh` and podman, and installs podman with apt where it is
missing.

The world-write policy is a BPF program on five tracing links pinned in
the host's bpffs. Before enabling it, the loader proves a root-owned mode
0666 file on `/` is writable as `nobody`; after, that the write fails with
`EACCES` while one owned by `nobody` still succeeds. A load or probe
failure fails the step; there is no fallback. On failure, partial
attachments are left in place: the job must not continue with untrusted
code, and reuse of that host is unsupported.

## The image and its pin

[`Containerfile.pin`](Containerfile.pin) is one `FROM` line naming the
image by tag and digest, which Dependabot moves together. The action runs
only the digest. Before pulling it, it checks the image's build
attestation with `gh attestation verify`, against the signer in
[`signer.json`](signer.json): agentic-job's release workflow on its main
branch, on a GitHub-hosted runner. Every host fix takes an agentic-job
release, then a pin update here.

| `config` | the action's [`hosted.toml`](hosted.toml) | A host configuration (agentic-job's `[sandbox]`, `[egress]` and `[setup]` tables).
